# Этап 7 — мелочи улиц, набережная и пляж (план, 2026-11-21)

Всё, что делает улицу живой: фонари, разметка и знаки, уличная мебель, набережная, пляж, террасы заведений, склоны
и площади. Состав сверен с кадрами Street View (`sv/paving`, `sv/slope`, `sv/oldtown`, `sv/seafront`, `sv/y1940`),
фото районов (`photos.md`) и точками OSM (`raw/points.json`). Часть плана [docs/sitges-plan.md](../sitges-plan.md).

## Решения пользователя

- 2026-11-18 (решение 6): **не делаем** деревянные столбы с проводами, зеркала на углах, разметку парковок.
- 2026-11-21:
  - **Припаркованные машины** — не в этапе 7 (возможно, этап 8).
  - **Жёлтая линия у бордюра** (запрет стоянки, на кадрах склонов) — не делаем.
  - **Пляжные мелочи** (лежаки, зонты, пляжные бары, вышки спасателей) — обязательно.
  - Реализация — отдельными сессиями по группам; эта сессия-оркестратор только планирует, сливает ветки и проверяет.
- Предложено и принято вместе с составом (2026-11-21):
  - светофоры — только по OSM (их 2), не на каждом углу, как в «Городе»;
  - знаки — только у точек STOP / «уступи дорогу» OSM и на въездах в односторонки, без «леса знаков»;
  - гидранты «Города» (с фонтаном при поломке) не переносить — на испанских тротуарах их почти нет;
  - столбики — только по точкам OSM и на краях пешеходных улиц старого города, сбиваемые; не вдоль всех тротуаров;
  - в старом городе — фонари на кронштейнах на стенах, не столбы;
  - кондиционеры и спутниковые тарелки на фасадах — не делаем (шум);
  - лодки уже есть в марине (`lm/marina.js`); на пляже — только если найдутся на фото;
  - бассейны вилл — плоской водой без геометрии, в конце.
- Уже сделано раньше, не повторять: плитка «панот» с гранитной кромкой, «зебры», ось улиц, велодорожки (этап 2), лодки
  марины (5–6), деревья в лунках (4б).

## Каркас (7.0)

Как в этапах 5–6: общий каркас первым, затем группы параллельно, каждая — только в своих файлах.

- **Раскладка** `js/maps/sitges/street.js` (после `trees.js`, `doors.js`): места у бордюра, у стены дома, на краю
  тротуара (`sitgesSpot…`); карта занятости — ворота, двери, стволы, переходы, вывески-стелы, углы — чтобы группы
  не ставили вещи друг на друга (`sitgesReserve`); порядок групп в раскладке фиксирован (A → B → C → D → E → F → G).
- **Постройка** `js/maps/sitges/street3d.js`: модель → инстансы по квадратам со скрытием вдали; сбиваемые через
  `Breakables` (как мелкие деревья в `trees3d.js`); неподвижные — круги / коробки в сетке столкновений; ночное
  свечение; теневые копии.
- **Заготовки групп** `js/maps/sitges/st/<группа>.js` — объект `{ ready, plan(C, S), build(K, S) }`, заранее
  прописаны в `index.html` и в порядке этапов: ветки групп не конфликтуют в общих файлах. Не готовая группа ничего
  не меняет (отпечаток мира тот же).
- **Данные**: новые виды точек OSM из таблицы выше → `data-points.js` (`tools/sitges/build.js`).
- **Отладка** `tools/sitges/street-debug.js`: `__stMap(area)` — схема сверху с местами и занятостью, `__stShots(points,
  { night })` — кадры в 3D, `__stInfo()` — сводка по группам (штук, треугольников, вызовов).
- **Фото**: режим `streetview.js` для произвольных точек (как `--lm`: `--look x,z --cams …`) в `raw/photos/street/<группа>/`.

## Сессии

Волнами по 2–3 сессии (5 параллельных сессий этапа 5–6 сожгли лимит до первого готового строения). Каждая сессия —
в своём git worktree, ветка от `main` после слияния прошлой волны. Сливает оркестратор (эта сессия) — после «да»
пользователя, затем `selfTest`, `__sitgesCheck()`, обновление плана.

| Волна | Сессии | Почему так |
|---|---|---|
| 0 | 7.0 каркас | всем группам нужны места, занятость, инстансы и заготовки |
| 1 | A фонари, B разметка и знаки, C уличная мебель | точечные вещи на улицах, разные файлы; нужны дальше для занятости |
| 2 | D набережная, F террасы | D меняет рельеф у берега; F — на тротуарах у фасадов, D — на стороне моря |
| 3 | E пляж, G склоны и площади | E ставит вещи по стене и лестницам D; G тоже правит рельеф и `ground.js` — не в одной волне с D |

## Правила для сессий групп

1. Свои файлы — `js/maps/sitges/st/<группа>.js` и архив `docs/sitges/st-<группа>.md`. Общие файлы (`street.js`,
   `street3d.js`, `index.html`, `build.js`, план) не править: нужен общий помощник — свой в своём файле, в отчёте
   предложить в каркас. Исключения: D и G — рельеф (`terrain.js`, `ground.js`) в своей полосе; F — тенты
   в `signs3d.js`. Новые глобальные имена — с префиксом группы, после — `node tools/deps.js --headers`.
2. Место — из данных (точки OSM, улицы, тротуары, участки), вид — по фото, не придумывать. Числа с фото — в свой архив.
3. Mid-poly: мелочь — десятки–сотни треугольников, инстансы, без новых источников света и своих шейдеров.
   Цену кадра не мерить (решение пользователя), в отчёте — штук, треугольников, вызовов отрисовки (`__stInfo()`).
4. Мелкое (контейнеры, урны, скамейки, столбики, знаки, фонари, лежаки, зонты, мебель террас) — сбиваемое;
   стены, лестницы, ограда променада — неподвижные.
5. Коммит после каждой готовой части (на случай лимита). Проверка: `__stShots` днём и ночью против фото,
   `node tools/cdp.js --eval "await __game.selfTest()"` — «ошибок нет», `__sitgesCheck()` с `--compare`,
   `node tools/deps.js --check`. В конце — отчёт: что сделано, цифры, что не похоже на фото.
