# Стальная Дуэль — заметки для ИИ-ассистента

3D-гонка на двоих (split-screen) на Three.js 0.160 + Rapier 0.21 (оба с CDN). Без сборки и npm: `index.html` открывается с диска.
Пользователь пишет по-русски; комментарии в коде, интерфейс и README — на русском.

## Как устроен код
- `js/**` — **обычные скрипты, не ES-модули** (иначе игра не откроется с диска). Все файлы делят одну глобальную область видимости. Порядок загрузки — массив `FILES` в `index.html`; новый файл добавлять туда после файлов, от которых он зависит.
- `THREE`, `RAPIER`, `RoomEnvironment`, `mergeGeometries` — глобалы, их выставляет модуль в `index.html`.
- В шапке каждого файла: описание, затем строки `// Определяет:` и `// Использует:` (какие глобалы задаёт и чьи берёт). Они **генерируются** — после добавления/переименования глобалов запусти `node tools/deps.js --headers`.
- Подробности механик (физика, трафик, разрушаемые объекты, время суток, производительность) — в `README.md` по разделам; читай только нужный раздел.

## Экономия токенов
- Где определено имя и кто его использует: `node tools/deps.js --who ИМЯ`. Зависимости файла: `node tools/deps.js js/race.js`. Это дешевле, чем искать grep-ом по всем файлам.
- Читай шапку файла (первые ~15 строк) прежде чем читать файл целиком; в больших файлах — только нужный раздел (`/* ==== */` и `/* ---------- */` — заголовки разделов).
- **Файлы данных реальных карт (`js/maps/*/data-*.js`) не читать и не искать по ним** — это сотни КБ чисел, их пишут скрипты из `tools/`. Что внутри и в каком формате — в шапке файла (первые строки, читать с ограничением) и в скрипте-генераторе. Grep их не видит (`.ignore` в корне), `tools/deps.js` берёт из них только имена верхнего уровня. Сырые скачанные данные (OSM, кадастр, рельеф) в репозиторий не кладутся.
- Город — по этапам: правка района → `blocks.js`, мостов/эстакады → `infra.js`, уличной мелочи → `streets.js` (раскладка) и `props.js` (3D). Порядок этапов — в `cityData()` и `buildCity()`.

## Подводные камни
- Уровень воды читать через `waterLevel(x, z)` (`js/world.js`), а не `world.water`: на «Побережье» река выше моря (`world.waterAt`). Границы карты — `world.boundsX/boundsZ` (по умолчанию `world.bounds`).
- **Город детерминирован** (зерно в `cityPlanBase()`): каждый новый вызов `R()` в середине раскладки меняет весь город после этого места. Если правка не должна менять город — сравни `__game.fingerprint('city')` (`dataHash`, `worldHash`) до и после, на свежей загрузке страницы до заезда.
- Этапы города обмениваются данными через объект-контекст (`C` в раскладке, `K` в постройке): этап берёт нужное деструктуризацией в начале и отдаёт новое через `Object.assign` в конце.
- Материалы, общие для многих мешей, помечены `userData.shared` (не уничтожать). Анимированное в статичных группах — `userData.dynamic = true`, иначе `optimizeStatic()` заморозит матрицу.
- Тень неподвижных объектов города отбрасывают не они сами, а «теневые копии» (`buildShadowProxies()` в `js/world.js`, вызывается в `cityBuildWorld()`): у исходных мешей `castShadow` выключен. Новый неподвижный объект с `castShadow = true`, добавленный до этого вызова, попадёт в копию сам; объект, который двигается или исчезает, помечай `userData.dynamic` — иначе его тень останется на месте.
- Новая карта окружения (`scene.environment`) должна пройти через `EnvProbe.bake()` (как в `Sky.apply()`), иначе первый кадр пойдёт со старыми цветами.
- Число источников света меняется только при загрузке заезда (иначе перекомпиляция шейдеров посреди игры).
- Цель производительности — ≥ 100 FPS вдвоём на встроенной Radeon 680M. Счётчик: клавиша Ё или `?fps` в адресе.
- Смена качества графики перезагружает страницу (MSAA задаётся при создании WebGL-контекста).
- На качестве «Минимум» (`QUAL.shadows = false`) карты теней нет совсем: `buildShadowProxies()` / `shadowProxyOf()` возвращают `null`, `castShadow` ни на что не влияет. Новые флаги качества добавляй во все три записи `QUALITY` так, чтобы `high`/`low` вели себя как раньше. `worldHash` на «Минимуме» отличается (нет теневых копий) — сравнивай отпечатки на одном уровне; `dataHash` от качества не зависит.
- Замер уровней качества стендом: `__setup({ px })` по умолчанию ставит px = 1,2 независимо от качества — для сравнения уровней передавай `px = Math.sqrt(1920*1200/(innerWidth*innerHeight)) * QUAL.scale`.

## Проверка изменений
1. Сервер: `.claude/launch.json` (python http.server). Если порт занят другой сессией — заведи конфиг с другим портом. Без панели браузера: `node tools/cdp.js --eval "await __game.selfTest()"` — свой сервер и безголовый Edge с настоящей видеокартой.
2. В консоли страницы: `await __game.selfTest()` — строит все карты, гоняет машины 4 с, включает ночь; отчёт текстом, «ошибок нет» = ок.
3. Рефакторинг генерации карт — `__game.fingerprint('city')` до и после (см. выше); «Ситжес» — `fingerprint('sitges')` и `__sitgesCheck()` с `--compare tools/sitges/check-base.json` (`docs/sitges-plan.md`, «Как проверять»).
4. Правка трафика — `await __game.trafficTest()` (Побережье: серпантин, мосты, деревня, долгий прогон) и `trafficTest({ map: 'city' })`.
5. Скриншот — только для визуальных правок. Быстрый старт заезда: `__game.startMatch('free')` (или `'race'`, `'solo'`, `'capture'`, `'bomb'`).
6. `node tools/deps.js --check` — шапки файлов актуальны.
7. Правка ради скорости — замер `tools/bench.js` (как пользоваться — README, «Производительность»): сравнивай варианты через `__ab()` на одной загрузке страницы; цифры разных загрузок расходятся на ±1 мс.
